# 校园流转业务系统 v0.1

需求依据：校园二手交易平台V2.0及UD-09。技术栈：Node.js（≥24，需内置node:sqlite）、SQLite、原生HTML/CSS/JS。无需npm安装第三方依赖。与课程模拟原型独立，不改动已整理的提交材料。

## 本地启动

在本目录终端执行：

```sh
npm run setup
npm start
```

浏览器访问 http://127.0.0.1:3000 。管理员用户名为admin，初始密码见自动生成的`.env`；不要把该文件加入提交包或仓库。setup不覆盖已有配置。管理员仅首次建库时初始化，修改.env不会重置已存在的密码。数据库在data/campus.sqlite，保存用户、认证、商品图片、订单及事件。重启保留数据。

首次没有商品或学生账号。分别注册卖家和买家，提交姓名学号；管理员线下核验后在工作台审核。卖家发布商品并上传实际PNG/JPEG，经管理员审核后买家可下单。不同身份可用浏览器独立配置文件，或退出后切换账号；没有原型的角色下拉框。

本地默认仅监听回环地址。跨网络部署前需配置HTTPS、COOKIE_SECURE=1、反向代理请求限制及备份，不把开发版直接作为公开服务。

## 当前实现

- 密码scrypt哈希、HttpOnly/SameSite会话cookie、24小时会话、CSRF令牌、5次失败锁定30分钟；服务端角色权限。
- 姓名学号认证、历史申请、同学号有效认证唯一、管理员确认线下核验并留审核记录。
- 商品出售/免费转让/交换、图片存SQLite、MIME及基础内容标识/大小/数量检查、20件配额、先审后上架、本人发布列表。
- 下单保存快照、交换私有提供项与差价、请求标识去重、SQLite事务和进行中唯一索引锁定目标。
- 卖家接单、接单前取消/拒绝、接单后申请取消与同意/拒绝/撤回、交付记录、双方本人确认完成。
- 服务端截止检查及60秒超时任务、订单事件、审核审计、本人通知/已读。

图片基础结构检查并非完整图像解码/恶意内容检测；公开部署前需要完整解码重编码及像素限制。SQLite和基础HTTP服务适合课程本地开发，不能据此承诺生产容量。

## 验证

```sh
npm test
```

使用内存数据库、真实本地HTTP请求和可控业务时钟；不使用或清空开发数据。当前集成用例覆盖三账号注册登录、认证唯一性/权限、商品审核、本人下单拒绝、同请求重试、占用拒绝、撤回取消、自同意拒绝、待回应交付拒绝、双确认、真实截止与超时释放、CSRF拒绝。前后端JS语法检查通过。

本轮尚未实际完成浏览器视觉/交互验收，接口测试通过不代替完整UI检查或35项VT通过。
