# macOS与Windows开发

## 统一环境

两端使用Node.js 24 LTS或兼容的更新版本（需支持node:sqlite），Git和现代浏览器。当前无第三方运行依赖，不需要全局安装框架、Python或Java。版本检查：`node --version`、`npm --version`。

从仓库根目录执行，下面两条在macOS终端和Windows PowerShell均适用：

```text
cd 业务系统
npm run setup
npm start
```

Windows中文路径用引号，例如 `cd "D:\课程项目\software-engineering\业务系统"`；macOS也可用带引号路径。浏览器打开 http://127.0.0.1:3000 。在本目录编辑.env设置PORT/HOST/ADMIN_PASSWORD，避免使用export或$env语法；重启生效。初始密码只用于首次创建管理员，不能用修改.env重置已有账号。

PowerShell如拦截npm.ps1，直接使用`npm.cmd run setup`、`npm.cmd start`、`npm.cmd test`，无需降低系统执行策略。

## 数据与提交

每位成员独立生成.env和data数据库，测试不共用真实账号数据；不要跨机器复制或提交正在运行的SQLite及-wal/-shm文件。使用备份/导出工具前先设计一致性方案。

源文件为UTF-8，.gitattributes统一代码行尾LF；不要批量改变历史原件行尾。文件路径严格大小写一致。Node脚本使用node:path，命令保持npm入口，禁止把开发者绝对路径写入应用。

## 测试

`npm test`使用内存SQLite与临时回环端口，无需额外数据库服务。当前真实运行验证平台为macOS；Windows需在队友电脑运行同一命令验证，未验证前不宣称兼容测试通过。Windows防火墙只在确有需要时允许本地开发，不默认改为0.0.0.0或公网开放。

## 需求与附件

仓库“需求分析”目录为整理后的三份主文档及编号附件；原型入口为附件/03_原型/index.html，图册入口为附件/02_图模型/图册.html，保持相对目录结构。检查工具里部分旧脚本仍依赖原工作区布局，不能当作跨平台业务启动依赖。
